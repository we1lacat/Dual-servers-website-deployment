## 0. 架构总览与安全设计原则

### 0.1 架构

```
                   公网用户
                      │
                      │ DNS: <DOMAIN> → B 公网 IP（唯一解析记录）
                      ▼
┌──────────────────────────────────────────────────┐
│  ★ B · Debian 13 · 2C2G · 备案机（唯一公网入口）  │
│  安全组入站: 80/443 对公网 · 51820/udp 限 A · 22 限运维出口│
│  ├─ Nginx :443（SSL 终止 + 反向代理 + 动静分离）    │
│  │   ├─ /assets/**  Vue dist 静态直出（长缓存 30d）│
│  │   ├─ /            SPA 兜底 try_files index.html│
│  │   └─ /api/**      proxy_pass → 127.0.0.1:8080 │
│  ├─ Tomcat 10.1 + JDK 21（仅本机回环监听）         │
│  │   └─ ROOT.war (Spring Boot 3 + SQLite + JWT)  │
│  ├─ SQLite <DATA_DIR>/we1l.db（WAL 模式）         │
│  ├─ Node Exporter（绑定隧道 IP :9100）            │
│  └─ 每日定时本地备份 → 隧道 rsync 推送 A          │
└──────────────┬───────────────────────────────────┘
               │ WireGuard UDP :51820（跨地域加密隧道）
               │ B:10.10.0.1 ←→ A:10.10.0.2
               ▼
┌──────────────────────────────────────────────────┐
│  ★ A · Alibaba Cloud Linux 3 · 2C2G · 纯内网角色  │
│  安全组入站: 51820/udp 限 B · 22 限运维出口 · ❌无80/443│
│  ├─ Prometheus + Grafana（监控中心，SSH 隧道访问） │
│  ├─ Alertmanager → 钉钉/邮件告警（可选）          │
│  ├─ rsync 备份接收 <BACKUP_DIR>/remote-backup/    │
│  └─ Fail2ban / 应急构建机（可选）                  │
└──────────────────────────────────────────────────┘
```

### 0.2 设计原则

| 原则 | 说明 |
| --- | --- |
| **单一公网入口** | 只有 B 对公网提供 Web 服务；DNS 仅一条 A 记录指向 B |
| **A 永不监听公网 80/443** | 安全组零规则；监控/备份面板一律经 SSH 隧道访问 |
| **最小暴露** | Tomcat 仅绑 127.0.0.1；Exporter 仅绑隧道 IP；SSH 限运维出口 |
| **凭据不落文档** | 密钥/密码由 `openssl rand` 生成后落盘 `chmod 600`，运行时注入 |
| **纵深防御** | 云安全组 + 主机防火墙双层；非 root 运维 + sudo |

### 0.3 角色与占位符（部署时全部替换）

| 占位符 | 含义 | 示例值（RFC 保留段） |
| --- | --- | --- |
| `<DOMAIN>` | 站点域名 | example.com |
| `<B_PUBLIC_IP>` | B 机公网 IP | 203.0.113.20 |
| `<A_PUBLIC_IP>` | A 机公网 IP | 198.51.100.10 |
| `<HOME_IP>` | 运维出口 IP | 1.2.3.4 |
| `<OPS_USER>` | 非 root 运维账号 | ops |
| `<DATA_DIR>` | 数据目录 | /opt/we1l |
| `<BACKUP_DIR>` | 备份接收目录 | /opt/we1l |
| `10.10.0.1 / 10.10.0.2` | WireGuard 隧道地址 | B / A |

> 跨地域无共享 VPC：跨机流量走公网承载的 WireGuard 加密隧道，上层配置一律使用隧道 IP，
> 对方公网 IP 只出现在 WireGuard `Endpoint` 与安全组规则中。

## 1. 安全组配置

按「默认入方向全拒绝、显式放行」原则编写。

### 1.1 B 机（`sg-b`）

| # | 方向 | 协议/端口 | 授权源 | 用途 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 入 | TCP 443 | 0.0.0.0/0 | HTTPS 主入口 | 唯一公网业务口 |
| 2 | 入 | TCP 80 | 0.0.0.0/0 | HTTP → 301 跳 443 | 仅跳转 |
| 3 | 入 | UDP 51820 | `<A_PUBLIC_IP>/32` | WireGuard 隧道 | **只允许 A** |
| 4 | 入 | TCP 22 | `<HOME_IP>/32` | SSH 运维 | 建议改高位端口 |
| — | 入 | 其他全部 | — | ❌ 不放行 | 9100/8080/3000 一律不对公网 |
| — | 出 | 全部 | 0.0.0.0/0 | 默认 | 不改 |

可选加固：追加拒绝 `TCP 8080 源 0.0.0.0/0`，防止误改监听后暴露。

### 1.2 A 机（`sg-a`）

| # | 方向 | 协议/端口 | 授权源 | 用途 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 入 | UDP 51820 | `<B_PUBLIC_IP>/32` | WireGuard 隧道 | **只允许 B** |
| 2 | 入 | TCP 22 | `<HOME_IP>/32` | SSH 运维 | — |
| — | 入 | TCP 80/443 | — | ❌ 零规则 | 合规铁律 |
| — | 入 | 3000/9090/9100 | — | ❌ 不对公网 | 走 SSH 隧道 |
| — | 出 | 全部 | 0.0.0.0/0 | 默认 | 需出网拉包/告警 |

### 1.3 验证

```bash
# 本机（运维出口）执行
curl -m 5 http://<B_PUBLIC_IP>/            # → 301
curl -m 5 https://<B_PUBLIC_IP>/ -k        # → HTML
nc -zv -w 3 <A_PUBLIC_IP> 443              # 应拒绝 ★ A 不见公网
nc -zv -w 3 <B_PUBLIC_IP> 8080             # 应拒绝 ★ Tomcat 不暴露
```

### 1.4 主机防火墙（第二层）

```bash
# ===== B 机 (Debian, ufw) =====
sudo apt install -y ufw
sudo ufw default deny incoming && sudo ufw default allow outgoing
sudo ufw allow 443/tcp && sudo ufw allow 80/tcp
sudo ufw allow from <A_PUBLIC_IP> to any port 51820 proto udp
sudo ufw allow from <HOME_IP> to any port 22 proto tcp
sudo ufw enable && sudo ufw status numbered

# ===== A 机 (Alibaba Cloud Linux, firewalld) =====
sudo systemctl enable --now firewalld
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<B_PUBLIC_IP>" port port="51820" protocol="udp" accept'
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<HOME_IP>" port port="22" protocol="tcp" accept'
sudo firewall-cmd --reload
```

监控端口在主机防火墙层放行**隧道网段**：
`ufw allow from 10.10.0.0/24 to any port 9100`（B）/ firewalld 同理（A）。

## 2. WireGuard 跨域隧道（部署首步）

```bash
# B (Debian)      A (Alibaba Cloud Linux)
sudo apt install -y wireguard        sudo yum install -y kmod-wireguard wireguard-tools
```

```bash
# 各自生成密钥对
wg genkey | sudo tee /etc/wireguard/server.key | wg pubkey | sudo tee /etc/wireguard/server.pub   # B
wg genkey | sudo tee /etc/wireguard/client.key | wg pubkey | sudo tee /etc/wireguard/client.pub   # A
# 通过受信渠道互换两份 .pub
```

```ini
# ===== B 机 /etc/wireguard/wg0.conf =====
[Interface]
PrivateKey = <B 私钥>
Address = 10.10.0.1/24
ListenPort = 51820
[Peer]
PublicKey = <A 公钥>
AllowedIPs = 10.10.0.2/32

# ===== A 机 /etc/wireguard/wg0.conf =====
[Interface]
PrivateKey = <A 私钥>
Address = 10.10.0.2/24
[Peer]
PublicKey = <B 公钥>
Endpoint = <B_PUBLIC_IP>:51820
AllowedIPs = 10.10.0.1/32
PersistentKeepalive = 25
```

```bash
sudo systemctl enable --now wg-quick@wg0
# A 机验证
ping -c 3 10.10.0.1 && sudo wg show
# Watchdog（A 机）
echo '* * * * * root ping -c 2 -W 3 10.10.0.1 >/dev/null 2>&1 || systemctl restart wg-quick@wg0' \
  | sudo tee /etc/cron.d/wg-watchdog
```

> `AllowedIPs` 只写隧道网段，不劫持默认路由。

## 3. B 机（应用机）：JDK 21 + Tomcat 10.1 + Nginx

### 3.1 安装

```bash
# JDK 21（Eclipse Temurin 官方源，LTS 至 2031）
curl -fsSL https://packages.adoptium.net/artifactory/api/gpg/key/public | sudo gpg --dearmor -o /usr/share/keyrings/adoptium.gpg
echo "deb [signed-by=/usr/share/keyrings/adoptium.gpg] https://packages.adoptium.net/artifactory/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/adoptium.list
sudo apt update && sudo apt install -y temurin-21-jdk
java -version    # openjdk 21

# Tomcat 10.1+（Debian 官方包：jakarta 命名空间，systemd 托管）
sudo apt install -y tomcat10
# 服务名 tomcat10；目录 /var/lib/tomcat10（webapps） /etc/tomcat10（conf）
```

> Tomcat 必须 10.x（jakarta.*，非 javax）。以 apt 包方式部署可获得原生 systemd 托管与目录规范，
> 相比手工解压包更易维护。

### 3.2 本机回环监听

编辑 `/etc/tomcat10/server.xml` 的 Connector：

```xml
<Connector port="8080"
           protocol="org.apache.coyote.http11.Http11Nio2Protocol"
           address="127.0.0.1"
           maxThreads="100" acceptCount="200" minSpareThreads="20"
           connectionTimeout="20000" compression="on" />
```

### 3.3 数据目录与密钥预生成

```bash
sudo mkdir -p <DATA_DIR>/{data,backup,bin,webroot,oom,ssl}
# JWT 密钥与管理员密码：落盘成文件，避免出现在进程列表/命令历史
sudo sh -c 'openssl rand -hex 32  > <DATA_DIR>/.jwt_secret'
sudo sh -c 'openssl rand -base64 12 > <DATA_DIR>/.admin_pwd'
sudo chmod 600 <DATA_DIR>/.jwt_secret <DATA_DIR>/.admin_pwd
```

### 3.4 构建并上传 WAR（开发机操作）

```bash
cd we1l-backend
mvn clean package -DskipTests
scp target/we1l-backend.war <OPS_USER>@<B_PUBLIC_IP>:/tmp/ROOT.war     # 传暂存区
ssh <OPS_USER>@<B_PUBLIC_IP> "sudo install -o tomcat -g tomcat -m 644 /tmp/ROOT.war /var/lib/tomcat10/webapps/ROOT.war"
```

> 部署为 `ROOT.war` → context path `/`，接口即 `/api/**`。

### 3.5 运行参数注入（/etc/default/tomcat10）

apt 包通过 `/etc/default/tomcat10` 注入 JAVA_OPTS：

```bash
sudo tee /etc/default/tomcat10 > /dev/null <<'EOF'
JAVA_OPTS="$JAVA_OPTS -Dfile.encoding=UTF-8 -server"
# 2GB 机器守 768M 堆上限
JAVA_OPTS="$JAVA_OPTS -Xms512m -Xmx768m -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=192m"
# JDK 21 Generational ZGC（不稳可回退 -XX:+UseG1GC）
JAVA_OPTS="$JAVA_OPTS -XX:+UseZGC -XX:+ZGenerational -XX:MaxGCPauseMillis=20"
# OOM 自愈：dump 留证 + 退出交给 systemd 拉起
JAVA_OPTS="$JAVA_OPTS -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=<DATA_DIR>/oom/ -XX:+ExitOnOutOfMemoryError"
JAVA_OPTS="$JAVA_OPTS -Djava.security.egd=file:/dev/./urandom"
# 应用配置（外置，不改 WAR；文件权限 600）
JAVA_OPTS="$JAVA_OPTS -DDB_PATH=<DATA_DIR>/data/we1l.db"
JAVA_OPTS="$JAVA_OPTS -DJWT_SECRET=$(cat <DATA_DIR>/.jwt_secret)"
JAVA_OPTS="$JAVA_OPTS -DJWT_EXPIRE_HOURS=8"
JAVA_OPTS="$JAVA_OPTS -DADMIN_USERNAME=admin"
JAVA_OPTS="$JAVA_OPTS -DADMIN_PASSWORD=$(cat <DATA_DIR>/.admin_pwd)"
JAVA_OPTS="$JAVA_OPTS -DCORS_ORIGINS=https://<DOMAIN>,https://www.<DOMAIN>"
EOF
sudo systemctl restart tomcat10
sleep 20 && sudo tail -50 /var/log/tomcat10/catalina.out
curl http://127.0.0.1:8080/api/profile   # 期望 code:0
```

### 3.6 Nginx（SSL + 动静分离 + 反向代理）

`因备案问题未由其他服务器接入，如需修改请自行阅读Nginx doc`

证书：云厂商免费 DV 证书（Nginx 格式）上传至 `<DATA_DIR>/ssl/`。

```bash
sudo apt install -y nginx
# 前端 dist 部署目录（本公开版统一定义）
sudo mkdir -p /var/www/<DOMAIN>-vue
```

```nginx
# /etc/nginx/sites-available/<DOMAIN>-ssl.conf
server {
    listen 80;
    server_name <DOMAIN> www.<DOMAIN>;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl http2;
    server_name <DOMAIN> www.<DOMAIN>;
    ssl_certificate     <DATA_DIR>/ssl/<DOMAIN>.fullchain.pem;
    ssl_certificate_key <DATA_DIR>/ssl/<DOMAIN>.privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 1d;
    add_header Strict-Transport-Security "max-age=31536000" always;

    client_max_body_size 20m;
    gzip on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/json application/javascript image/svg+xml;

    root  /var/www/<DOMAIN>-vue;
    index index.html;

    location ~* \.(js|css|woff2?|png|jpg|jpeg|gif|svg|ico)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }
    location / {
        try_files $uri $uri/ /index.html;   # SPA 兜底
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8080;   # ★ 不带末尾斜杠，原样转发 /api/**
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout    30s;
        proxy_buffers 16 8k;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/<DOMAIN>-ssl.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

> `proxy_pass` 不带 URI 时 `/api/xxx` 原样转发；多写一个 `/` 会剥前缀导致 404。

### 3.7 Node Exporter（绑定隧道 IP）

```bash
sudo useradd -r -s /usr/sbin/nologin nodeexp 2>/dev/null
# 下载 node_exporter 最新稳定版二进制至 /usr/local/bin（略）
sudo tee /etc/systemd/system/node-exporter.service > /dev/null <<'EOF'
[Unit]
Description=Node Exporter (wireguard only)
After=network.target wg-quick@wg0.service
[Service]
User=nodeexp
ExecStart=/usr/local/bin/node_exporter --web.listen-address=10.10.0.1:9100
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now node-exporter
```

### 4.2 备份接收端（rrsync 受限）

> A 机必须已装 `rsync`（提供 rrsync 受限包装；rrsync 运行时依赖 /usr/bin/rsync）。

```bash
# A 机：建接收用户与目录
sudo useradd -m -d /home/backup backup
sudo mkdir -p <BACKUP_DIR>/remote-backup
sudo chown backup:backup <BACKUP_DIR>/remote-backup
# 确认 rsync 存在
which rsync rrsync   # 缺则 yum install -y rsync
```

```bash
# B 机：生成推送专用密钥（专用密钥 ≠ 运维主密钥）
sudo ssh-keygen -t ed25519 -f /root/.ssh/id_backup -N '' -C backup-push
sudo cat /root/.ssh/id_backup.pub   # 复制内容
```

```bash
# A 机：授权（restrict + 限定 rrsync 只能写接收目录）
RRSYNC=$(command -v rrsync)
PUB='<上一步复制的公钥内容>'
echo "no-port-forwarding,no-pty,no-agent-forwarding,no-X11-forwarding,command=\"$RRSYNC <BACKUP_DIR>/remote-backup\" $PUB" \
  | sudo tee /home/backup/.ssh/authorized_keys
sudo chmod 600 /home/backup/.ssh/authorized_keys && sudo chown -R backup:backup /home/backup/.ssh
```

## 5. 每日备份（B → 隧道 → A）

```bash
# /opt/we1l/bin/backup.sh（B 机，root 拥有）
cat > /tmp/backup.sh <<'EOF'
#!/bin/sh
set -e
TS=$(date +%Y%m%d-%H%M)
SRC=<DATA_DIR>/data/we1l.db
DST=<DATA_DIR>/backup

# 1. 一致性热备（VACUUM INTO 官方推荐，顺带压缩）
sqlite3 "$SRC" ".timeout 5000" "VACUUM INTO '$DST/we1l-$TS.db'"
# 2. 本地保留 7 份轮转
ls -t $DST/we1l-*.db | tail -n +8 | xargs -r rm
# 3. 隧道推送 A（rsync over ssh，专用密钥）
rsync -az -e "ssh -i /root/.ssh/id_backup -o StrictHostKeyChecking=no" \
    $DST/we1l-$TS.db backup@10.10.0.2:<BACKUP_DIR>/remote-backup/
# 4. WAL checkpoint
sqlite3 "$SRC" "PRAGMA wal_checkpoint(PASSIVE);"
echo BACKUP_OK $TS
EOF
sudo install -m 700 /tmp/backup.sh <DATA_DIR>/bin/backup.sh && rm /tmp/backup.sh
echo '0 3 * * * root <DATA_DIR>/bin/backup.sh >> /var/log/we1l-backup.log 2>&1' | sudo tee /etc/cron.d/we1l-backup
```

**端到端验证**（部署后验证）：

```bash
# B 机手动执行
sudo <DATA_DIR>/bin/backup.sh            # 期望 BACKUP_OK
# 双机一致性校验
sudo sha256sum <DATA_DIR>/backup/we1l-*.db          # B 本地
ssh backup@10.10.0.2 "sha256sum <BACKUP_DIR>/remote-backup/we1l-*.db"   # A 接收（或经 A 运维账号查）
# 两份哈希应完全一致
```

**月度恢复演练（留证）**：把最近备份拷回 B，起临时库验证数据完整：

```bash
# A 机
scp <BACKUP_DIR>/remote-backup/we1l-<日期>.db <OPS_USER>@10.10.0.1:/tmp/verify.db
# B 机
sqlite3 /tmp/verify.db 'SELECT count(*) FROM note;'
```

## 6. 全链路验证清单

在运维出口逐条执行：

| # | 检查项 | 命令 | 期望 |
| --- | --- | --- | --- |
| 1 | HTTPS 首页 | `curl -I https://<DOMAIN>/` | 200 + 证书有效 |
| 2 | HTTP 跳转 | `curl -I http://<DOMAIN>/` | 301 → https |
| 3 | SPA 刷新 | `curl -I https://<DOMAIN>/service` | 200（非 404） |
| 4 | 公开接口 | `curl https://<DOMAIN>/api/profile` | JSON code:0 |
| 5 | 鉴权拦截 | `curl -o /dev/null -w '%{http_code}' https://<DOMAIN>/api/admin/stats` | 401 |
| 6 | 登录链路 | 浏览器 /login → admin | 正常进入后台 |
| 7 | A 无公网 Web | `nc -zv -w 3 <A_PUBLIC_IP> 443` | 拒绝/超时 ★ |
| 8 | B 无 8080 | `nc -zv -w 3 <B_PUBLIC_IP> 8080` | 拒绝/超时 ★ |
| 9 | 隧道健康 | A 机 `ping -c3 10.10.0.1` | 0% loss |

## 8. 凭据与安全基线

| 项 | 说明 |
| --- | --- |
| 默认账号 | `admin` / `<DATA_DIR>/.admin_pwd` 文件内容（首次启动自动 BCrypt） |
| Token | HS512 JWT（`JWT_SECRET` ≥32 字节随机），默认 8h；前端 localStorage；401 自动跳登录 |
| `/api/admin/**` | 必须 `Authorization: Bearer xxx`，否则 401 |
| 密钥文件 | `.jwt_secret`/`.admin_pwd` 权限 600；**绝不出现在文档/Git/命令历史** |
| 运维账号 | 禁止 root 直连；统一非 root + sudo；SSH 限运维出口 IP |
| 备份密钥 | `/root/.ssh/id_backup` 专用，与运维主密钥隔离；对端 rrsync 受限 |
| 全站 HTTPS | 无明文 JWT；HSTS 上线稳定后 max-age=31536000 |

## 9. 常见故障排查

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 隧道不通 | 安全组 51820 未放行对端 | 核对 §1 规则；`sudo wg show` 看 handshake |
| WireGuard 反复断 | NAT 会话超时 | A 侧 `PersistentKeepalive = 25` |
| Tomcat 启动 javax 报错 | Tomcat ≤9 | 必须 10.x（jakarta） |
| 接口 404 带前缀 | WAR 未命名 ROOT.war | 改名 ROOT.war |
| /api 前缀丢失 | proxy_pass 末尾多写 `/` | `proxy_pass http://127.0.0.1:8080;` |
| 刷新 /admin 404 | 缺 SPA 兜底 | `try_files $uri $uri/ /index.html;` |
| 502 | Tomcat 未启动/监听错 | `curl 127.0.0.1:8080/api/profile` 分段定位 |
| SQLITE_BUSY | 并发写 | Hikari 限 4 连接 + busy_timeout=5000 |
| 备份推送失败 | 隧道断/授权变 | 先 ping 10.10.0.2，再 `ssh -i /root/.ssh/id_backup -v` 排障 |
| 备份报 rrsync 缺 rsync | A 机未装 rsync | A 机 `yum install -y rsync` |
